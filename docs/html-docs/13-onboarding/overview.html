Onboarding

Tutoriel guidé en 9 étapes avec modals, tooltips et validation progressive. L'état est persisté en JSON dans le modèle User (champ onboardingState), synchronisé en temps réel via SSE, avec protection anti-régression et gestion admin.

Fonctions de mutation

Le module onboardingState.js fournit des fonctions pures de mutation :

  • markModalCompleted(state, stepKey) — Marquer un modal comme complété
  • markTooltipClosed(state, stepKey) — Marquer un tooltip comme fermé
  • markStepCompleted(state, stepKey) — Marquer une étape comme complétée et l'ajouter à completedSteps[]
  • updateCurrentStep(state, stepIndex) — Mettre à jour l'étape courante
  • markOnboardingCompleted(state) — Terminer l'onboarding (hasCompleted: true)
  • updateStep4Preconditions(state) — Mettre à jour les préconditions de l'étape 4 (step4.cvGenerated)
  • normalizeOnboardingState(state) — Normaliser l'état (ajouter les champs manquants)
  • validateOnboardingState(state) — Valider la cohérence de l'état

API Onboarding

Le endpoint /api/user/onboarding gère 4 méthodes HTTP :

Méthode Action Détails
GET Lire l'état Cache en mémoire avec TTL de 1000ms. Retourne l'état normalisé.
PUT Mettre à jour Mise à jour de l'étape courante. Protection anti-régression : retourne 409 si currentStep recule.
PATCH Mise à jour partielle Merge partiel de l'état (ex : un seul champ d'une étape). Cache invalidé après mise à jour.
POST Actions 3 actions : complete (terminer), skip (passer), reset (réinitialiser).
Anti-régression — La route PUT retourne une erreur 409 (Conflict) si le client essaie de diminuer le currentStep. Cela empêche les conditions de course entre plusieurs onglets ou appareils.

Synchronisation temps réel

Chaque modification de l'état d'onboarding émet un événement SSE :

// Après mise à jour en DB
dbEmitter.emit('onboarding:updated', {
  userId,
  data: updatedState,
});

// Le client React reçoit l'événement via SSE
// et met à jour le hook useOnboarding()

Le endpoint SSE écoute aussi onboarding:reset pour gérer la réinitialisation admin.

Factory i18n

La fonction createOnboardingSteps(t) dans onboardingSteps.js génère les 9 étapes avec :

  • targetSelector — Sélecteur CSS de l'élément cible pour le tooltip
  • tooltip — Configuration du tooltip (titre, description, position)
  • modal — Configuration du modal avec carousel (écrans multiples) — présent aux étapes 1, 2, 5, 7, 8, 9
  • validation — Règles de validation pour passer à l'étape suivante
  • preconditions — Conditions requises pour afficher l'étape (ex : étape 4 nécessite step4.cvGenerated)
  • fallback — Comportement alternatif si la précondition échoue

Toutes les chaînes de caractères sont passées par la fonction de traduction t() pour supporter l'internationalisation.

Mapping modals → étapes

Le module onboardingConfig.js définit le mapping STEP_TO_MODAL_KEY entre les étapes et les clés de modals dans l'état :

Étape Clé modal
welcome (étape 0) welcome

ai_generation (étape 2) step2
ai_review (étape 5) step5
optimization (étape 7) step7

Actions disponibles

// Objet ONBOARDING_ACTIONS exporté par onboardingSteps.js
ONBOARDING_ACTIONS = {
  complete: 'complete',  // Terminer l'onboarding normalement
  skip: 'skip',          // Passer l'onboarding
  reset: 'reset',        // Réinitialiser (admin)
}

Admin

L'interface admin dispose de deux endpoints dédiés :

Endpoint Description
/api/admin/onboarding/analytics KPIs : totalUsers, started, completed, skipped, inProgress, stuck, completionRate, skipRate, avgCompletionTime, healthScore. Funnel par étape, analyse des abandons, stats modals, timeline.
/api/admin/onboarding/reset Réinitialisation de l'état d'onboarding d'un utilisateur. Émet onboarding:reset via SSE.
